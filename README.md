# Система учёта компьютерного оборудования колледжа

Учебная практика 2026 Проект **LoLGG**

## Цель проекта
Создать работоспособное приложение на Python для учёта компьютерного
оборудования, его работоспособности и конкретного нахождения.

## Содержание

#### Формат хранения данных
**База данных - JSON-файл** `data/inventory.json`. Это массив объектов.
Каждая запись - карточка оборудования.


## Описание и проблема
В колледже информация об оборудовании ведётся на бумаге и может теряться.
При уходе или увольнении ответственного лица теряются знания о том, где
находится конкретное оборудование.

**Проблема:** невозможно быстро определить местоположение устройства;
неизвестно, какая аппаратура рабочая, какая требует настройки или починки;
отсутствует нормальная среда для быстрой проверки наличия и
работоспособности техники.

## Инструкция как пользоваться нашим приложением

## Пользовательские сценарии

Ниже — 10 сценариев использования приложения. Каждый сценарий содержит
шаги и ожидаемый результат. Сценарии соответствуют текущей версии
(меню: просмотр, поиск, добавление, изменение, удаление, выход).

Поля карточки оборудования:
`id` (инвентарный номер), `name` (наименование), `cabinet` (кабинет),
`condition` (состояние), `responsible` (ответственное лицо).



### Сценарий 1. Первый запуск приложения

**Предусловие:** файла `data/inventory.json` изначально есть.

**Шаги:**
1. Запустить `python main.py`.
2. Выбрать пункт `1`.

**Ожидаемый результат:**
- Приложение открывается без ошибок, меню отображается.
- Список пуст - программа не падает и не выводит исключений.
- После выбора пункта `1` можно увидеть список обборудования которые уже написаны в файл `data/inventory.json`.

### Сценарий 2. Просмотр списка существующих записей

**Предусловие:** в `data/inventory.json` есть 2–3 записи.

**Шаги:**
1. Запустить приложение.
2. Выбрать пункт `1`.

**Ожидаемый результат:**
- Для каждой записи выводятся все её поля:
  `id : INV-0012`, `name : Obiect`, `cabinet : каб. 102`,
  `condition : рабочее`, `responsible : Петров П.П.`
- Записи выводятся в том порядке, в котором хранятся в файле.

### Сценарий 3. Добавление новой записи с предложенным номером

**Шаги:**
1. Выбрать пункт `3`.
2. Ввести название: `Монитор Dell P2422H`.
3. Программа предлагает `INV-0014`  нажать Enter (согласиться).
4. Ввести кабинет: `каб. 312`.
5. Ввести состояние: `требует ремонта`.
6. Ввести ответственное лицо: `Петров П.П.`.

**Ожидаемый результат:**
- Сообщение: «Запись 'Монитор Dell P2422H' добавлена.»
- Запись сохранена в `data/inventory.json`.
- При просмотре списка (пункт `1`) новая запись отображается.

### Сценарий 4. Добавление записи с вручную заданным номером

**Шаги:**
1. Выбрать пункт `3`.
2. Ввести название: `Системный блок HP ProDesk`.
3. Не соглашаться с предложенным номером — ввести вручную:
   `INV-2024-00157`.
4. Заполнить кабинет, состояние, ответственное лицо.

**Ожидаемый результат:**
- Сообщение об успешном добавлении.
- В `data/inventory.py` появилась запись с номером
  `INV-2024`.
- При следующем добавлении `generate_inventory_number` предложит
  номер после максимального существующего.

### Сценарий 5. Попытка добавить запись с дублирующимся номером

**Предусловие:** в базе уже есть запись с номером `INV-0001`.

**Шаги:**
1. Выбрать пункт `3`.
2. Ввести название: `Принтер`.
3. Ввести номер вручную: `INV-0001`.
4. Заполнить остальные поля.

**Ожидаемый результат:**
- Сообщение: «Запись с номером INV-0001 уже существует.»
- Запись **не добавлена**, файл `data/inventory.json` не изменён.
- Программа не завершается аварийно, возвращается в меню.

### Сценарий 6. Добавление записи с пустыми или пробельными полями

**Шаги:**
1. Выбрать пункт `3`.
2. Ввести название, состоящее только из пробелов (`"   "`).
3. Заполнить остальные поля корректно.

**Ожидаемый результат:**
- Сообщение: «Строка не может остаться пустой.»
- Запись не добавлена.
- Программа возвращается в меню без аварийного завершения.

**Проверить отдельно:** то же поведение при пустом `id`, `cabinet`,
`condition`, `responsible`.

### Сценарий 7. Поиск существующего оборудования по номеру

**Шаги:**
1. Выбрать пункт `2`.
2. Ввести номер: `INV-0002`.

**Ожидаемый результат:**
- Выводятся все поля найденной записи:
  `id : INV-0002`, `name : Монитор`, `cabinet : каб. 101`,
  `condition : рабочее`, `responsible : Петров П.П.`

### Сценарий 8. Поиск отсутствующего номера и повторный поиск

**Предусловие:** в базе нет записи `INV-9999`.

**Шаги:**
1. Выбрать пункт `2`.
2. Ввести номер: `INV-9999`.
3. Убедиться, что показано сообщение об отсутствии.
4. Снова выбрать пункт `2`, ввести **существующий** `INV-0001`.
5. Снова выбрать пункт `2`, ввести **несуществующий** `INV-7777`.

**Ожидаемый результат:**
- На шаге 2: «Такого инвентарного номера нет».
- На шаге 4: запись `INV-0001` найдена и выведена.
- На шаге 5: снова «Такого инвентарного номера нет».
