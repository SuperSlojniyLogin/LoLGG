# Система учёта компьютерного оборудования колледжа

Учебная практика 2026 Проект: **LoLGG**

## Цель проекта
Создать работоспособное приложение на Python для учёта компьютерного
оборудования, его работоспособности и конкретного нахождения.

## Содержание

#### Формат хранения данных
**База данных - JSON-файл** `data/inventory.json`. Это массив объектов.
Каждая запись - карточка оборудования.


## Описание и проблема
В колледже информация об оборудовании ведётся на бумаге и может теряться.
При уходе или увольнении ответственного лица теряются знания о том, где
находится конкретное оборудование.

**Проблема:** невозможно быстро определить местоположение устройства;
неизвестно, какая аппаратура рабочая, какая требует настройки или починки;
отсутствует нормальная среда для быстрой проверки наличия и
работоспособности техники.

# Ключевые требования
1. Записи выводятся в виде простой читаемой таблицы с номерами оборудований, наименованием, кабинетом и состоянием оборудования. При пустой записи выводится “Записей нет”.

2. Должны присутствовать такие поля как инвентарный номер, наименование, кабинет, состояние, они заполняются и проверяются.

3. Состояние выбирается только из допустимых значений. При изменении записи значение категории сохраняется.

4. Поле “Ответственное лицо” опционально, оно должно отображаться в списке, если заполнено.

5. Формат JSON валиден и содержит все поля записи. База данных JSON.

6. Обязательные поля проверяются на корректность. При ошибке в строке она не сохраняется и показывается что не так.

7. Можно изменять оборудование и сохранять изменения.


## Инструкция как пользоваться нашим приложением
#### Список ограничений
1. Нужно вводит корректные данные номеров объектов в таких пунктак как пункт 2, 3, 4, 5 номер объекта можно будет указывать тремя спосабами:
      - 'INT-0001'
      - '0001'
      - '1'
2. Если в номере писать - он заменится на 0 так что лучше пишите см 1 пункт.
3. Для пользователя справка в `condition` или же состояние лучше всего использовать эти обозначения для ясности и корректности понимания.
       - `Исправно`
       - `Требует ремонта`
       - `Списано`
4. В пункте удаления объекта необходимо писать номер объекта как написано в 1 пункте
5. Необходимо в пункты писать корректные данные.


### Инструкция как запустить нашу программу по шагам

2. Открыть зип-файл.
3. Перенести все фалы из зип-файла в новую созданную вами папку.
4. Открыть PyCharm.
5. В появившемся окне нажать на четыре полоски около левого верхнего угла, нажать на Open, в появившемся окне нажать на значёк домик, далее нажать на папку Рабочий стол, в этой папке найти ВАШУ созданную папку, нажать на неё и нажать на ОК.
6. Далее нажать на кнопку The Window.
7. Дальше нажать на кнопку Terminate или же нажмити на кнопку Trust Project.
8. Откроется программа точней папки.
9. Вам необходимо нажать на папку main.py.
10. И далее необходимо нажать на зелёный треугольник в самом верху экрана около зелёного жука и Current Flle.
11. ИИИ поздравляю вы открыли программу!!!
12. Можете мышкой нажать перед надписью "Выберете цифру: " и написать цифру 1.
13. Вы увидети хронящиеся оборудования и программа опять спросить, что необходимо сделать.

### Реализованные функции для пользователя
1. Пользователь при вводе числа '1' в программу может увидеть всё оборудование которое есть в файле `data/inventory.json`.
2. При вводе числа '2' в программу пользователь после может написать номер оборудования и ему выведит это конкретный объект/оборудование.
3. Пользователь при вводе числа '3' в программу может добавить новое оборудование, ему после ввода '3' необходимо написать название, ввести номер, кабинет, состояние и ответственное лицо.
4. Пользователь при вводе числа '4' в программу может изменить уже существующие оборудование, но прежде ему необходимо написать его номер.
5. Пользователь при вводе числа '5' в программу может удалить уже существующие оборудование, но прежде ему необходимо написать его номер.
6. Пользователь при вводе числа '0' в программу может выйти из программы.

## Примеры пользовательских сценариев

### Сценарий 1. Первый запуск приложения

**Предусловие:** файла `data/inventory.json` изначально есть.

**Шаги:**
1. Запустить `python main.py`.
2. Выбрать пункт `1`.

**Ожидаемый результат:**
- Приложение открывается без ошибок, меню отображается.
- Список пуст - программа не падает и не выводит исключений.
- После выбора пункта `1` можно увидеть список обборудования которые уже написаны в файл `data/inventory.json`.

### Сценарий 2. Просмотр списка существующих записей

**Предусловие:** в `data/inventory.json` есть 2–3 записи.

**Шаги:**
1. Запустить приложение.
2. Выбрать пункт `1`.

**Ожидаемый результат:**
- Для каждой записи выводятся все её поля:
  `id : INV-0012`, `name : Obiect`, `cabinet : каб. 102`,
  `condition : рабочее`, `responsible : Петров П.П.`
- Записи выводятся в том порядке, в котором хранятся в файле.

### Сценарий 3. Добавление новой записи с предложенным номером

**Шаги:**
1. Выбрать пункт `3`.
2. Ввести название: `Монитор Dell P2422H`.
3. Программа предлагает `INV-0014`  нажать Enter (согласиться).
4. Ввести кабинет: `каб. 312`.
5. Ввести состояние: `требует ремонта`.
6. Ввести ответственное лицо: `Петров П.П.`.

**Ожидаемый результат:**
- Сообщение: «Запись 'Монитор Dell P2422H' добавлена.»
- Запись сохранена в `data/inventory.json`.
- При просмотре списка (пункт `1`) новая запись отображается.

### Сценарий 4. Добавление записи с вручную заданным номером

**Шаги:**
1. Выбрать пункт `3`.
2. Ввести название: `Системный блок HP ProDesk`.
3. Не соглашаться с предложенным номером — ввести вручную:
   `INV-2024-00157`.
4. Заполнить кабинет, состояние, ответственное лицо.

**Ожидаемый результат:**
- Сообщение об успешном добавлении.
- В `data/inventory.py` появилась запись с номером
  `INV-2024`.
- При следующем добавлении `generate_inventory_number` предложит
  номер после максимального существующего.

### Сценарий 5. Попытка добавить запись с дублирующимся номером

**Предусловие:** в базе уже есть запись с номером `INV-0001`.

**Шаги:**
1. Выбрать пункт `3`.
2. Ввести название: `Принтер`.
3. Ввести номер вручную: `INV-0001`.
4. Заполнить остальные поля.

**Ожидаемый результат:**
- Сообщение: «Запись с номером INV-0001 уже существует.»
- Запись **не добавлена**, файл `data/inventory.json` не изменён.
- Программа не завершается аварийно, возвращается в меню.

### Сценарий 6. Добавление записи с пустыми или пробельными полями

**Шаги:**
1. Выбрать пункт `3`.
2. Ввести название, состоящее только из пробелов (`"   "`).
3. Заполнить остальные поля корректно.

**Ожидаемый результат:**
- Сообщение: «Строка не может остаться пустой.»
- Запись не добавлена.
- Программа возвращается в меню без аварийного завершения.

**Проверить отдельно:** то же поведение при пустом `id`, `cabinet`,
`condition`, `responsible`.

### Сценарий 7. Поиск существующего оборудования по номеру

**Шаги:**
1. Выбрать пункт `2`.
2. Ввести номер: `INV-0002`.

**Ожидаемый результат:**
- Выводятся все поля найденной записи:
  `id : INV-0002`, `name : Монитор`, `cabinet : каб. 101`,
  `condition : рабочее`, `responsible : Петров П.П.`

### Сценарий 8. Поиск отсутствующего номера и повторный поиск

**Предусловие:** в базе нет записи `INV-9999`.

**Шаги:**
1. Выбрать пункт `2`.
2. Ввести номер: `INV-9999`.
3. Убедиться, что показано сообщение об отсутствии.
4. Снова выбрать пункт `2`, ввести **существующий** `INV-0001`.
5. Снова выбрать пункт `2`, ввести **несуществующий** `INV-7777`.

**Ожидаемый результат:**
- На шаге 2: «Такого инвентарного номера нет».
- На шаге 4: запись `INV-0001` найдена и выведена.
- На шаге 5: снова «Такого инвентарного номера нет».
